# @vortex/solver-sdk

Typed TypeScript SDK for Vortex solvers: a REST client generated from the
backend's OpenAPI document, a WebSocket client with auto-reconnect and
replay, and signing helpers that match the server byte for byte. No NestJS
dependency.

## Install

```bash
npm install @vortex/solver-sdk @stellar/stellar-sdk
```

## Quickstart

```ts
import { Keypair } from "@stellar/stellar-sdk";
import { VortexRestClient, VortexWsClient, signAccept, signFill, signWsAuth } from "@vortex/solver-sdk";

const keypair = Keypair.fromSecret(process.env.SOLVER_SECRET!);
const rest = new VortexRestClient("https://api.vortex.trade");
const ws = new VortexWsClient({
  url: "wss://api.vortex.trade/ws",
  signAuth: () => signWsAuth(keypair), // or: token: "<SEP-10 JWT>"
});

ws.on("event", async (event) => {
  if (event.type !== "intent_created") return;
  const id = (event.intent as { intentId: string }).intentId;
  await rest.accept(id, signAccept(keypair, id, { network: "testnet" }));
  // ...settle on Stellar, then:
  await rest.fill(id, signFill(keypair, id, "1000000", "<stellar tx hash>", { network: "testnet" }));
});
ws.connect();
```

A complete runnable solver is in [`examples/example-solver.ts`](examples/example-solver.ts).

## WebSocket client

- **Auth**: `signAuth` (signed `{ type: "auth" }` frame, re-sent on every
  reconnect) or `token` (SEP-10 JWT, sent as `?token=`). Without either the
  connection is anonymous and receives the public feed.
- **Ordering**: `event` fires strictly in ascending `seq` order, once per
  sequence number. Sequence numbers are global across backend replicas.
- **Reconnect / replay**: on reconnect, or when a gap appears (e.g. events
  dropped while the client was a slow consumer), the client sends
  `{ type: "replay", fromSeq }` and delivers the missing events before newer
  ones. Persist `client.position` and pass it as `resumeFrom` to resume
  after a restart.
- **`resync_required`**: the gap is older than the server's replay buffer —
  re-fetch state over REST (`listOpenIntents()`).
- **`rate_limited`**: the server's per-connection rate limit was hit; slow
  down, or the connection will be closed.

## Signing

`signAccept`, `signFill` and `signCancel` require the Stellar `network` option
for version 2 messages, and generate a fresh nonce with a five-minute expiry by
default. `signWsAuth` remains a separate connection-authentication scheme. The
legacy intent signing helpers remain available when the network option is
omitted, but the server accepts those signatures only while
`ALLOW_LEGACY_STELLAR_SIGNATURES=true`. Shared v1/v2 vectors are checked
against the server implementation in CI.

EVM-originated creation and cancellation use `signEvmCreateIntent` and
`signEvmCancelIntent` with the chain ID and escrow verifying contract. Auction
clients can call `rest.getAuctionPrice(id)` and listen for `auction_price`
events; the accepted amount is locked into the intent and is the minimum fill.

## Versioning

The SDK's `major.minor` tracks the backend API version (`info.version` in
the OpenAPI document; recorded as `vortexApiVersion`). `npm run
check:version` enforces this. The REST types in `src/generated/` are
regenerated by `npm run generate:client` at the repository root. CI dry-runs
`npm publish` on pull requests and publishes on `v*` tags.
